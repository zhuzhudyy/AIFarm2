# Town V2 AI 请求、令牌、延迟与费用预算

> 状态：目标规范，尚未实现。本文为 Town V2 的容量与成本护栏，不表示当前 Unity 客户端或 `Server/` 已实现共享限流、token 记账或费用门禁。

## 1. 预算目的与估算假设

AI 是可选的角色表达增强层，不能成为胡萝卜农田、共享背包、游戏时间、动作、会话状态、共同活动或存档的权威。预算耗尽、网关关闭或模型不可用时，四名居民仍必须通过确定性本地路径完成演示。

默认预算基于以下明确假设：

- 参考演示固定为 4 名居民：`resident-001`/芽芽、`resident-002`/阿木、`resident-003`/小穗、`resident-004`/墨墨；显示名不用于记账。
- 预算采用 10 分钟滑动窗口：任意单调墙钟时刻都回看此前 10 分钟的已使用和预约额度；新演示、UI 重置或读档不能清空尚未自然过期的记录。
- 一块共享 3×3 胡萝卜农田和一个共享演示背包由 Unity 本地模拟；模型不生成每地块动作。
- 参考窗口最多包含 1 次玩家命令解释、1 次返回整段 2–6 句脚本的成对会话、每居民 1 次高层意图决定，以及共享的可选表达/反思额度。
- 唯一的公开玩家命令解释请求由确定性 town coordinator 固定指定 `resident-001` 为 owner；它只携带公开命令和公开只读上下文，不读取该居民的私有记忆。本地验证通过后才发布 `PublicTownEvent`。
- 一个居民的一次发言计一个 conversation turn；每次成对会话最多 6 turn 或 30 秒墙钟，先到即终止。
- 所有请求都具有一个明确 `ResidentId`，经过同一个 `AiRequestCoordinator` 和共享网关。
- Unity `API SETUP` 的启动/就绪探测是本地进程配置，不计作模型请求；只有协调器实际派发的模型调用才进入预算。UI 的共享模型默认值是 `deepseek-v4-flash`，但其价格仍必须按部署时批准的精确模型配置填写，不能由默认值推断。
- 默认不自动重试。未来若增加重试，每次上游尝试都作为新远程请求单独计数、计 token 和计费。
- 本文不假定任何厂商、模型或币种价格。价格必须在部署时从已批准的价格表填入版本化配置。

“远程请求”在本文中指协调器实际派发、意图调用可计费模型的一次尝试。为保守起见，即使服务端随后返回本地 fallback，该已派发尝试仍消耗一个请求槽。排队后在派发前取消、应用层精确缓存命中和纯本地 fallback 不消耗远程请求或远程 token。

## 2. 可计算量与公式

对预算窗口中的第 `j` 个已派发请求，定义：

- `U_j`：未缓存的计费输入 token；
- `K_j`：提供商报告的缓存输入 token；
- `O_j`：计费输出 token，包含提供商按输出计费的隐藏推理 token（如有）；
- `m_j`：实际使用的模型/价格层；
- `P_in(m)`、`P_cache(m)`、`P_out(m)`：每 1,000,000 token 的输入、缓存输入和输出单价；
- `F_j`：该请求的其他明确固定费用，没有则为 0；
- `t_enqueue_j`、`t_deliver_j`：单调时钟的入队和交付时刻。

对任意时刻 `t`，令 `W(t)` 为准入时间位于 `(t - 10 分钟, t]` 的预算记录；窗口总量为：

```text
R       = 已派发远程请求数
T_in    = Σ(U_j + K_j)
T_out   = ΣO_j
L_e2e_j = t_deliver_j - t_enqueue_j

C_window = Σ[
    U_j / 1,000,000 * P_in(m_j)
  + K_j / 1,000,000 * P_cache(m_j)
  + O_j / 1,000,000 * P_out(m_j)
  + F_j
]
```

若提供商没有单独的缓存输入价格，则把 `K_j` 合并到 `U_j`。若某种额外计费项目无法写入 `F_j`，不能宣称费用预算已覆盖它。

单一模型、无缓存折扣时，默认窗口 token 上限对应的保守费用上限为：

```text
B_cost_default = 0.018 * P_in + 0.003 * P_out + 12 * F_request
```

多模型路由时，按每个 operation 的最大 token 预约量和其允许模型中最高批准单价求和。不得用宣传页上的临时价格硬编码；`PriceConfig` 必须记录来源、币种、生效日期、模型精确标识和审核时间。

如果价格配置缺失或过期，token/request 护栏仍有效，但费用值必须显示为 `unknown`，不能显示为 0。要求硬费用门禁的构建应失败关闭远程模式并使用本地 fallback。

## 3. 默认硬上限

| 维度 | 默认上限 | 说明 |
| --- | --- | --- |
| 预算窗口 | 10 分钟滑动窗口 | 使用单调墙钟；预算记录以准入时刻归属，满 10 分钟后自然移出。 |
| 远程请求 | 12 次/窗口 | 已派发后不退还请求槽。 |
| 输入 token | 18,000/窗口 | 未缓存与缓存输入之和。 |
| 输出 token | 3,000/窗口 | 使用提供商计费口径；没有 usage 时按预约上限扣减。 |
| 单请求端到端 deadline | 3.0 秒 | 从入队到交付，包含排队、传输、提供商、解析、校验和切换 fallback。 |
| 全局在途并发 | 2 | 包含正在访问共享网关的请求。 |
| 每居民在途并发 | 1 | 以稳定 `ResidentId` 计，不能按显示名规避。 |
| 派发速率 | 突发 2，补充 1 次/秒 | 上游配置更低时采用更低值；窗口 12 次上限仍优先。 |
| 自动重试 | 0 | 故障立即本地回退。 |
| 成对会话 | 6 turn 或 30 秒 | 任一居民发言一次计 1 turn；先到即停止。 |

3.0 秒是用户可见的绝对 deadline，而不是“排队后再等 3 秒”。协调器在入队时设置 `deadline = enqueueMonotonic + 3.0s`；排队时间过长、到期仍未完成或回包在到期后到达时，立即取消或标记 stale，交付确定性本地结果。产品指标始终按 `L_e2e` 计算。

### 3.1 参考 operation 分配

下表的请求数和单请求 token 上限恰好组成窗口总上限。输出上限必须同时配置到模型调用，并由响应大小/schema 再限制。

| Operation | 优先级 | 次数上限 | 单次输入上限 | 单次输出上限 | 确定性 fallback |
| --- | --- | ---: | ---: | ---: | --- |
| `InterpretPlayerIntent` | P0 | 1 | 1,200 | 200 | 本地白名单命令解释器 |
| `ConversationScript` | P0 | 1 | 3,000 | 700 | 一次生成 2–6 句本地模板脚本 |
| `ResidentIntentDecision` | P1 | 4 | 1,700 | 250 | 每居民本地日程/公开目标规则；`propose_town_event` 仅形成待校验提案 |
| `GenerateExpression` | P2 | 2 | 1,000 | 250 | 按事件、居民和版本选择固定表达模板 |
| `GenerateReflection` | P2 | 4 | 1,250 | 150 | 按目标结果、居民和版本选择简短固定反思模板 |
| **合计** |  | **12** | **18,000** | **3,000** |  |

次数上限是远程增强配额，而不是业务功能上限。超过配额的玩家输入、话轮、居民决定和表达仍可执行，但必须使用本地处理器。完整胡萝卜闭环不消耗任何必需的远程额度。

单次上下文超限时，先由本地确定性选择器删除最低优先级记忆，只保留完成 operation 必需的合法信息；仍超限则直接 fallback。不得截断 JSON 结构、ResidentId、版本、允许意图集合或会话边界。

## 4. 默认算例

一个 10 分钟窗口实际使用如下：

| Operation | 次数 | 实际输入/次 | 实际输出/次 | 输入小计 | 输出小计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 玩家命令解释 | 1 | 900 | 120 | 900 | 120 |
| 成对会话脚本 | 1 | 2,400 | 500 | 2,400 | 500 |
| 四居民高层意图 | 4 | 1,500 | 200 | 6,000 | 800 |
| 表达 | 2 | 800 | 160 | 1,600 | 320 |
| 反思 | 4 | 1,000 | 120 | 4,000 | 480 |
| **合计** | **12** |  |  | **14,900** | **2,220** |

该算例满足 `12 / 18,000 / 3,000` 三项硬上限。假定没有缓存折扣、所有调用使用同一价格层，费用是：

```text
C_example = 0.0149 * P_in + 0.00222 * P_out + 12 * F_request
```

代入部署时批准的价格即可得到对应币种金额；本文故意不填入厂商价格。

整段会话脚本只有 1 次远程请求，其远程等待上界为 3 秒，且仍受会话 30 秒总墙钟限制。整个窗口 12 个请求全部串行达到 deadline 时，远程等待暴露上界为 36 秒，但这些等待不得暂停游戏时间或阻塞本地农田执行。

## 5. 预算记账与准入算法

协调器维护一个带稳定 `BudgetScopeId` 的 `BudgetLedger`，每条记录保存准入单调时间、`RequestId` 和 `ResidentId`。每次准入先移出已满 10 分钟的记录；演示重置、读档和显示名变化均不更换 scope 或提前释放额度。只有新进程启动或经明确授权开始一个全新运行会话时才创建新 scope，普通 `New Demo` 不能借此绕过限额。准入顺序固定如下：

1. 校验居民、operation、请求世代、允许意图集合和 3 秒 deadline；无效则不入队并本地处理。
2. 查询符合隐私规则的精确缓存；命中后仍做 schema 和 stale 校验，但不消耗远程额度。
3. 按 operation 的“单次最大值”预约一个请求槽、输入 token 和输出 token。使用最大值而非乐观平均值，保证所有在途请求同时达到上限也不会透支。
4. 检查窗口总额、operation 次数、费用预约、优先级保留量、全局/居民并发和上游限制；任一不满足则立即 fallback 或在剩余 deadline 内排队。
5. 派发时把请求槽标为已消费。派发前取消/过期可释放预约；派发后失败、拒答或 fallback 不退还请求槽。
6. 完成时用提供商 usage 对账并释放未使用的 token/费用预约。缺少 usage 时保留整笔单次上限扣减，并记录 `usage_missing=true`。
7. 响应通过 schema、allowed intent、ResidentId、状态版本、会话 turn 和 deadline 校验后才交付；否则交付本地结果。晚到结果只记遥测，不得应用。

始终保持以下不等式：

```text
已使用 + 所有排队/在途预约 <= 对应窗口上限
```

本地已知的完整序列化提示必须在派发前用与模型匹配的、版本固定的 tokenizer 计数。没有可靠 tokenizer 时，不使用字符数冒充精确 token，而是预约该 operation 的全部单次上限。若提供商报告值意外超过本地预约，记录预算违例、熔断后续远程调用并 fallback；该情况使验收失败。

## 6. 优先级、限流与公平性

### 6.1 优先级

- **P0 交互：** 玩家命令解释、合法的当前会话回合。
- **P1 决策：** 由显式领域事件触发的居民高层意图决定；完成的合法双人会话可允许 `propose_town_event`，但它不新增端点，只形成由 Unity 再校验的 `TownEventProposal`。
- **P2 表达：** 非必需台词、反思和装饰性增强。

P2 只有在派发后仍至少保留 4 个请求槽、6,000 输入 token 和 1,000 输出 token 给 P0/P1 时才可准入。预算紧张时先关闭 P2，再让 P1 转本地；P0 也不得突破硬上限，而是即时走本地路径。

已在传输中的请求默认不抢占；若实现安全取消，可取消 P2 为 P0 腾出并发位，但已派发请求仍计数。任何抢占都不能把旧回包应用到新状态。

### 6.2 公平性与并发

同一优先级按居民做 round-robin，再按入队序号排序。四名居民的软公平份额是任意 10 分钟滑动窗口各 3 次远程派发；它不是硬配额。当其他居民没有同级等待项时可借用未使用份额，但全局 12 次和 operation 上限不可突破。

协调器同时执行：

- 全局 semaphore 为 2；
- `ResidentId` semaphore 为 1；
- 派发 token bucket 容量 2、每秒补充 1；
- 与上游 RPM/TPM/并发配置取更严格者；
- 每次检查剩余 deadline，预计无法在 3 秒内完成时不再派发。

成对会话的两个居民轮流成为请求 owner；同一 turn 只能有一个有效请求。会话结束会取消两名参与者对应此会话的全部排队/在途项，不影响他们其他已失效状态的安全检查。

## 7. 缓存策略与隐私

缓存用于减少重复远程调用，不能成为绕过居民隔离或 stale guard 的通道。

### 7.1 应用层精确缓存

只允许缓存无副作用、严格 schema 的结果。缓存键至少包含：

```text
Operation + ResidentId + ModelId + SchemaVersion + PromptVersion
+ AllowedIntentSetHash + CanonicalInputHash
+ ResidentStateVersion/ConversationVersion（只要上下文依赖状态）
```

规则如下：

- 所有键都含 `ResidentId`，即使输入看似公开，也不跨居民复用角色输出。
- 含私有记忆的正文不进入可读缓存键，只保存带 salt 的摘要；缓存内容与日志不得暴露原文。
- 玩家命令解释可在同一居民、同一 schema/prompt 版本和相同规范化输入下精确复用，默认 TTL 10 分钟。
- 会话回复、反思以及依赖可变私有记忆的输出默认不做跨请求应用缓存；仅允许同一 `RequestId` 的幂等重放。
- 读档、居民 epoch 变化、prompt/schema 升级和会话结束使相关缓存立即失效。
- 缓存命中仍验证当前请求 ID 映射、允许意图、状态版本和 deadline；不命中时不能退化为模糊语义缓存。

### 7.2 提供商提示缓存

提供商侧 prefix/prompt cache 命中仍算一次远程请求，`K_j` 仍计入 18,000 输入 token，只在费用公式中使用已配置的缓存单价。不得假设缓存一定免费。

## 8. 降级与熔断

降级顺序固定、可观察且不改变模拟结果：

1. 在合法范围内压缩上下文：只选择该居民最高相关度的有限记忆和必要公开事实。
2. P2 表达/反思全部改用本地模板。
3. P1 居民意图全部改用本地日程和公开目标规则。
4. P0 达到硬上限、deadline 或网关故障时也立即使用本地命令解释/会话模板。
5. 连续超时、无效 schema、usage 超预约或上游限流达到熔断阈值后进入 `LocalOnly`；最早冷却 30 秒并通过显式健康检查后才可半开一次，仍须满足滑动窗口预算。

默认熔断阈值为最近 10 分钟连续 3 次远程失败。schema 越权、usage 超预约或凭据配置错误属于严重失败，可一次即熔断。熔断只关闭远程增强，不暂停动作、会话清理、时间或农田闭环。

每个 fallback 以规范化输入、`ResidentId`、领域事件 ID/会话 turn、状态版本和模板版本作为稳定选择依据。相同快照与输入必须得到相同结果，不使用网络状态、墙钟随机数或字典遍历顺序选择台词。

## 9. 遥测与审计

每个请求记录结构化事件，不记录 API key、完整 prompt、玩家原文、私有记忆或完整会话正文。Unity 自动启动路径中的 Key 只通过自有子进程环境传递，不写磁盘、命令行或启动/就绪日志；匹配外部网关的复用不会应用新输入的 Key。允许字段包括：

- `BudgetScopeId`、滑动窗口起止单调时间、本地 `RequestId`、`ResidentId`、operation、priority；
- schema/prompt/model/price-config 版本；
- 请求世代、世界版本、可选 conversation ID/turn（使用不含正文的标识）；
- 入队、派发、首字节、完成和交付时间，以及 queue/transport/validation/end-to-end 毫秒；
- 预约和实际的输入、缓存输入、输出 token；
- 预约/估算费用、币种、价格配置 ID，或显式 `cost_unknown`；
- cache hit、远程/本地来源、结果类型、fallback/熔断/stale 原因；
- 响应大小、schema 校验结果、上游请求 ID 和取消结果。

聚合指标至少包括：

- 窗口和 operation 的请求数、token、费用与剩余额度；
- 全局及每居民队列深度、在途峰值和软份额使用；
- `L_e2e` 的 p50/p95/max、3 秒 deadline 命中率；
- cache hit、fallback、timeout、rate-limit、invalid-schema、stale 和 circuit-open 比率；
- 私有数据策略拒绝数、跨居民访问拒绝数和 late-apply 数。

原始遥测保留周期和访问权限由部署环境另行配置；无论如何，调试模式也不能记录密钥或私有正文。

## 10. 验收门槛

预算实现必须在四居民并发、故障注入和预算耗尽场景下同时满足：

1. 任意时刻 `used + reserved` 均不超过 12 请求、18,000 输入和 3,000 输出；费用预约不超过由批准 `PriceConfig` 计算的 `B_cost_default`。
2. 每个 P0/P1/P2 请求从入队起最多 3.0 秒交付“已验证远程结果或确定性本地结果”；排队不能延长该 deadline。
3. 观测到的全局在途峰值不超过 2，每个 `ResidentId` 不超过 1；显示名相同或变化不能绕过限制。
4. 成对会话在第 6 个 turn 后或 30 秒到达时立即结束；对应晚到回包应用数为 0。
5. 状态切换、读档、会话关闭和新目标导致的 stale 回包应用数为 0；取消失败也不得改变此结果。
6. 预算耗尽、熔断、网关关闭、超时、拒答、超长/额外字段/非法意图响应均有本地结果，未处理异常和永久等待为 0。
7. 每个已派发请求都有权威 usage 或完整单次上限扣减；未记账请求为 0，费用公式可用相同输入复算。
8. 应用缓存跨居民命中为 0；私有记忆正文出现在缓存键、日志或其他居民提示中的次数为 0。
9. P2 不能消耗为 P0/P1 保留的容量；同级队列在有可用额度时按居民 round-robin，无单居民永久饥饿。
10. 在 `LocalOnly`、12 次额度已用完以及全部远程调用失败三种情况下，固定分片的四名居民仍能完成播种、浇水、施肥、除草和收获，最终共享背包为 `0/0/0/9`；合法 HarvestDinner 仍能按本地规则完成或安全取消。

性能测试可以给计时器采样误差设置测试工具容差，但产品记录中的 deadline 仍是 3.0 秒，不能把容差写成更长的运行时等待。

## 11. 配置变更规则

请求数、token、deadline、会话边界、并发、价格层、prompt/schema 版本或 fallback 的任何调整都必须：

- 更新版本化配置和本文件中的估算假设；
- 重新计算最坏 token 与费用公式；
- 重跑预算、隐私、stale、会话和离线闭环验收；
- 在 PR 中说明旧值、新值、原因、证据和回滚方式。

不得为了提高远程成功率而扩大模型的状态修改权限、延长 3 秒用户可见 deadline，或让失败绕过确定性本地路径。

本地网关进程是否成功启动、复用或停止不重置 `BudgetScopeId`，也不退还已派发额度。Unity 只停止自己启动且握手匹配的进程；匹配外部网关只复用、不接管。启动、配置、鉴权、sidecar 缺失或就绪失败均立即保留本地 fallback 能力。桌面发布若声明支持 UI 自动启动，必须随包提供可运行 gateway sidecar 及依赖；该打包成本与模型 token/请求费用分开核算。
