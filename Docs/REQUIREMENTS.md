# AIFarm MVP 需求

## 1. 文档目的

本文把 `origin_requirements.md` 收敛为一个可演示、可验收的最小范围。目标是在体块化 Unity 3D 场景中，让用户用自然语言要求一名 AI NPC 完成一块 3×3 农田的胡萝卜种植全流程。

## 2. 固定范围

| 项目 | 固定约束 |
| --- | --- |
| 角色 | 恰好一个 NPC |
| 农田 | 3×3，共九个地块；按从左到右、从前到后的固定顺序编号 1–9 |
| 作物 | 仅胡萝卜 |
| 视觉 | Unity 基础体块和简单材质，不要求美术资产 |
| 必经步骤 | 播种、浇水、施肥、除草、收获 |
| 初始时间 | 第 1 天 08:00 |
| 初始背包 | 胡萝卜种子 9、肥料 9、胡萝卜 0 |
| 单块产出 | 消耗 1 粒种子和 1 份肥料，最终产出 1 个胡萝卜 |
| AI 服务 | 本地 Python FastAPI 网关，可关闭且不影响完整游戏流程 |

## 3. 核心用户流程

1. 进入演示后，玩家看到一名 NPC、九个空地块、游戏时间和背包数量。
2. 玩家输入“请把这块 3×3 农田全部种上胡萝卜，并照料到收获”。
3. 系统将输入归一化为“完成整块胡萝卜种植周期”的高层目标，NPC 给出一句确认表达。
4. Unity 确定性规划器生成固定流程：依次播种九块地、浇水、施肥，等待作物进入需除草状态，除草，等待成熟，再收获。
5. 当前时间、动作、地块状态和背包数量在执行期间可观察。
6. 完成后九个地块回到空闲状态，种子和肥料均为 0，胡萝卜为 9，NPC 给出完成表达。

## 4. 功能要求

- **FR-01 场景基线：** 运行时只出现一个 NPC、一块 3×3 农田和胡萝卜这一种作物。
- **FR-02 自然语言入口：** 玩家可提交文本命令；系统必须支持核心流程中的中文示例及含义相同的表达。
- **FR-03 目标边界：** LLM 只可解释受支持的高层目标并生成 NPC 的台词/表情标记，不得决定动作序列、地块坐标、时间、库存或产量。
- **FR-04 确定性规划：** Unity 根据已验证目标和权威游戏状态生成动作，九个地块采用固定编号顺序。相同初始状态和目标必须得到相同动作顺序及结果。
- **FR-05 动作规则：** 每个动作在执行前检查前置状态；前置条件不满足时不得改变世界状态。
- **FR-06 时间：** Unity 持有并推进加速游戏时间；作物的需除草和成熟状态只由确定性的游戏时间规则触发。
- **FR-07 背包：** 背包始终显示种子、肥料和胡萝卜数量，并在相应动作成功后立即更新。
- **FR-08 可观察性：** UI 显示游戏时间、背包、当前高层目标和 NPC 当前动作；地块外观能区分关键阶段。
- **FR-09 离线运行：** FastAPI 或外部 LLM 不可用时，本地目标解析和固定角色表达接管，完整流程仍可完成。
- **FR-10 可选 AI 增强：** FastAPI 可返回受支持的高层目标及更自然的角色表达。Unity 必须验证响应，并继续使用同一个确定性规划器。

## 5. 非功能要求

- 核心流程不需要网络、API 密钥或 Python 服务。
- AI 请求失败、超时或响应无效时，最多等待 3 秒即回退到离线路径，不冻结主循环。
- API 密钥不得写入 Unity 资源、源文件、文档示例或 Git。
- 一次完整离线流程应在 120 秒真实时间内完成，适合现场演示。
- Unity 是农田、NPC、时间和背包状态的唯一权威来源。

## 6. 明确不在范围内

不实现多 NPC、多作物、多人游戏、战斗、经济系统、动物、天气、程序化世界、存档、语音输入、云端部署、复杂寻路、精细数值平衡或正式美术。FastAPI/LLM 不承担游戏模拟、动作规划或状态存储。

## 7. 完成定义

`ACCEPTANCE_TESTS.md` 中所有强制测试通过，离线主流程可重复完成；可选 AI 增强不改变动作顺序和最终状态；没有扩大上述固定范围。
