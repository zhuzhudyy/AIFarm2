# AIFarm Town V2 验收测试

## 1. 文档状态与判定规则

本文是 `TOWN_V2_REQUIREMENTS.md` 的目标验收规范，不表示 Town V2 已实现。除 `TV2-AT-024` 明确标为 Conditional 外，所有测试均为 **Mandatory**。只有某项的全部预期结果都有证据时才记为通过；未实现、无法观察、依赖人工修改权威状态、超时、未处理异常或只有“看起来正常”而无断言，均记为失败。

每个测试必须使用新的测试夹具或全新 Play Mode 会话，不得依赖上一项残留状态。失败时保存首个违反不变量的结构化事件、相关 Resident/Goal/Conversation/Request/Point ID 和当时的权威状态快照；日志不得包含私有记忆全文、完整私聊、提示或凭据。

## 2. 固定测试配置

### 2.1 参考世界

- Unity Editor：`6000.5.10f1`。
- 居民：`resident-001`/芽芽、`resident-002`/麦麦、`resident-003`/林林。
- 世界：一个共享时钟、一块编号 1–9 的 3×3 胡萝卜田、一份共享背包。
- 初始时间：第 1 天 08:00；九块地为空。
- 初始背包：胡萝卜种子/水/肥料/胡萝卜 = `9/9/9/0`。
- 固定公开命令：

> 请大家一起把这块 3×3 农田全部种上胡萝卜，并完成浇水、施肥、除草和收获。

- 固定分片：`resident-001` → 1–3，`resident-002` → 4–6，`resident-003` → 7–9。

### 2.2 必备测试替身与证据

实现必须提供不进入正式构建的测试接缝：

- 可暂停、延迟、乱序完成、返回无效数据并记录并发数的 `ControllableAiGateway`；
- 可单调推进的墙钟和游戏时钟；除真实演示时限测试外，可用虚拟墙钟无等待地验证 3 秒与 30 秒边界；
- 可暂停移动/动作提交的导航与动作反馈替身；
- 可查询但不能绕过领域规则的居民注册表、预约表、请求协调器计数器和结构化事件导出；
- 可为每个 ResidentId 放入唯一哨兵文本的测试记忆仓库。

自动化测试放在 `My project/Assets/Tests/EditMode/` 或 `My project/Assets/Tests/PlayMode/`，文件名以 `Tests.cs` 结尾。时间边界同时测试 `边界前一最小单位`、`恰好等于边界` 与 `边界后一最小单位`；生产超时仍以单调墙钟为准，不能使用游戏时间或 `Time.timeScale`。

## 4. 协作农务、动作与预约

### TV2-AT-005 离线三居民公开农务闭环（Mandatory）

**追踪：** `TV2-CMP-01`、`TV2-WLD-01`、`TV2-ACT-01`、`TV2-NFR-01`

**前置：** 全新参考世界；FastAPI 关闭且远程模式指向不可达地址；使用真实秒表。

**步骤：**

1. 提交固定公开命令并启动 120 秒倒计时。
2. 导出公开父目标、三个居民子目标、每次动作开始/提交、阶段屏障、库存和地块状态事件。
3. 观察完整的播种、浇水、施肥、等待杂草、除草、等待成熟和收获。
4. 完成后再运行 5 秒，确认没有重复动作。

**预期：** 若创建可选远程解释请求，其 RequestOwner 固定为 `resident-001`，上下文只有公开命令/公开只读信息且不含 001 私有记忆；本地解释成功后由 Unity 发布父目标。父目标显式为 PublicTownEvent；三个子目标分别归属 001/002/003，并严格操作 1–3/4–6/7–9。每个分片内升序；九块均完成当前阶段后才出现下一阶段的领域提交。各居民任一时刻最多一个动作，且至少出现两个居民同时在不同点位行动的可观察区间。每块地每阶段恰好提交一次；最终九块为空闲、背包 `0/0/0/9`，用时不超过 120 秒。远程调用失败不阻塞流程，完成后不再扣减或产出。

### TV2-AT-006 行动与会话互斥（Mandatory）

**追踪：** `TV2-ACT-01`、`TV2-CON-01`

**前置：** 用动作替身暂停 `resident-001` 的一个已开始但未提交动作；002 和 003 空闲。

**步骤：**

1. 在 001 动作暂停期间再给 001 请求第二个动作，并请求 001↔002 会话。
2. 同时让 002 执行一个不冲突动作，记录所有居民 ActiveAction/ActiveConversation 数量。
3. 完成 001 的原子动作，再重新发起 001↔003 会话。

**预期：** 001 的第二动作不会并发启动；001↔002 会话在 001 忙时确定性等待或明确拒绝，且不出现半创建会话。002 可以独立行动。001 动作只提交一次；结束后 001↔003 可正常建立。任何时刻每名居民 ActiveAction ≤ 1、ActiveConversation ≤ 1，且两者不同时为 1。

### TV2-AT-007 点位竞争、令牌与释放（Mandatory）

**追踪：** `TV2-RSV-01`、`TV2-RSV-02`

**前置：** 建立一个测试交互点 `point-test-01`；三居民空闲；可暂停持有者动作。

**步骤：**

1. 在同一调度批次让 001 和 002 请求 `point-test-01`，记录裁决和令牌；让失败者尝试直接执行。
2. 持有者完成动作，确认等待者随后能获得新一代令牌。
3. 用旧令牌尝试释放新租约。
4. 分别在失败、取消、租约超时、居民禁用、新演示、场景卸载和读档路径重复预约，检查清理。
5. 用相同入队条件重复三次并比较获胜者。

**预期：** 任一时刻预约表对该点最多一个持有者；同批次按既定队列序号/ResidentId 规则得到相同获胜者。失败者不能执行或提交。旧令牌不能影响新租约。每种终止路径均释放或作废预约且无泄漏；重新申请生成更高代次的新令牌。

### TV2-AT-008 共享状态竞争与提交前复检（Mandatory）

**追踪：** `TV2-WLD-01`、`TV2-RSV-01`、`TV2-AI-04`

3. 记录地块状态、库存、动作结果和领域事件。

**预期：** 只有一个居民取得点位并成功播种；种子只从 2 变为 1。另一意图因预约或“地块非空”明确失败/重规划，不能再次扣减、覆盖作物或产生第二个成功事件。任何模型候选都没有直接写入世界。

### TV2-AT-009 日程隔离、单次触发与优先级（Mandatory）

**追踪：** `TV2-SCH-01`、`TV2-ISO-01`、`TV2-AI-01`

**前置：** 给三居民配置同一游戏时间边界但不同的白名单活动和逻辑地点；001 同时有未完成公开农务子目标。

3. 完成 001 的当前原子动作与农务子目标，再推进调度。
4. 只修改 002 的下一条日程，比较 001/003。

**预期：** 每居民在该边界恰好收到一次自己的日程事件；不会按帧重复。001 先按规定完成已开始动作和已接受农务目标，之后才执行仍有效的日程；002/003 按各自日程行动。修改 002 不影响另外两者。日程触发和选择无需远程 AI，且没有从 `Update()` 新建远程请求。

## 5. 成对会话

### TV2-AT-010 会话准入、成对身份与轮流发言（Mandatory）

**追踪：** `TV2-CON-01`、`TV2-CON-03`、`TV2-ACT-01`

**前置：** 三居民均空闲；网关返回即时有效的角色话语。

**步骤：**

1. 建立 001↔002 会话并记录 ConversationId、参与者和首位说话者。
2. 在其 Active 期间请求 001↔003、002↔003 及重复的 002↔001 会话。
3. 推进四个话轮，记录说话者、正文投递和三居民占用。

**预期：** 首场会话恰有两个不同参与者和唯一 ID；001/002 的新会话均失败或确定性排队，不创建第二个 Active 会话，003 保持未占用。四个话轮严格交替，无同一居民连续两轮；每轮所有者与请求 ResidentId 一致。正文只投递给 001/002。

### TV2-AT-011 六话轮硬上限（Mandatory）

**追踪：** `TV2-CON-02`、`TV2-CON-03`、`TV2-AI-06`

**前置：** 001↔002 会话；网关可立即返回至少十条有效话语。

**步骤：**

1. 让会话连续推进并记录每次已展示发言、请求和计数。
2. 在第六次发言后继续推进五个调度周期。

**预期：** 恰好六条发言被接受并展示，计数为 1–6，发言者交替；第六条后状态以 `MaxTurns` 结束并释放双方占用。不得创建第七个请求、额外告别语或隐藏远程调用。两名参与者各自记住有效正文，003 不记住。

### TV2-AT-012 三十秒墙钟超时与迟到响应（Mandatory）

**追踪：** `TV2-CON-02`、`TV2-AI-07`、`TV2-NFR-03`

**前置：** 002↔003 会话；测试接缝允许手动触发下一话轮而不改变生产状态机规则；使用可控单调墙钟，游戏时间暂停。

**步骤：**

1. 不触发足以达到 6 轮的发言，把墙钟推进到会话 Active 后 29.000 秒；此时手动触发下一话轮，并让网关持有请求。
2. 推进到 29.999 秒并记录状态，再推进到恰好 30.000 秒及一个 UI 帧。
3. 在 30 秒后、该请求自身 3 秒 deadline 前返回一条 Schema 有效的迟到话语。

**预期：** 29.999 秒时尚未因总时限结束；30.000 秒时立即以 `Timeout` 闭合，释放双方占用和相关预约，并取消/作废请求。即使话轮请求尚未达到自己的 3 秒期限，迟到话语也因会话版本失效而不显示、不计话轮、不写记忆、不重新打开会话；游戏时间暂停不影响墙钟超时，UI 始终响应。

## 6. AI 协调、校验、预算与回退

### TV2-AT-013 共享协调器与禁止从 Update 发起远程请求（Mandatory）

**追踪：** `TV2-AI-01`、`TV2-AI-02`

**前置：** 注入只允许共享协调器调用的记录型网关；没有用户、日程、会话或结果事件。

**步骤：**

1. 空闲运行 1,000 个 Update 帧，记录逻辑请求和传输启动数。
2. 分别触发一个公开用户提交、一个会话轮次和一个目标结果事件。
3. 检查每条调用的创建事件、调用者、RequestId、ResidentId、版本、关联 ID、入队时间和截止时间。
4. 使用 `rg` 检查网关/传输引用，并由程序集依赖测试证明居民表现与动作执行模块不能直接持有远程传输。

**预期：** 空闲 Update 不创建或启动任何远程调用。三种离散事件只经共享协调器创建请求；所有信封字段完整且所有者正确。公开命令解释的 RequestOwner 为 `resident-001`，且上下文不含其私有记忆；会话请求所有者为当前说话者。不存在居民、气泡、行动执行器或普通 Update 直接调用远程网关的路径。

### TV2-AT-014 Schema、意图白名单与模型只读边界（Mandatory）

**追踪：** `TV2-AI-03`、`TV2-AI-04`、`TV2-WLD-01`

**前置：** 记录权威世界快照；网关可依次返回构造的 JSON。

**步骤：**

1. 分别返回：未知意图、额外字段、缺失字段、错误类型、超长文本、未知 ResidentId、错误 ConversationId、候选集合外目标。
2. 分别返回含位置、低层动作数组、时间、库存、农田、关系、日程、记忆所有者或存档修改字段的响应。
3. 返回一个合法 `CompleteCarrotLifecycle` 高层意图，检查后续计划来源。

**预期：** 前两步每个响应均在应用前被严格拒绝并记录校验原因，未知字段不会被忽略；随后使用对应本地回退。拒绝响应本身不改变权威快照。合法高层意图只能进入 Unity 本地分派器；模型响应不含且不能决定地块动作序列，所有后续变化仍通过领域前置检查和原子提交。

### TV2-AT-015 全远程路径的三秒端到端回退（Mandatory）

**追踪：** `TV2-AI-05`、`TV2-NFR-01`、`TV2-NFR-03`

**前置：** 对命令解释、居民意图决定、表达、会话话轮、反思五类操作建立固定输入；可控网关支持不可达、异常、拒绝、限流、无效 Schema、永久挂起和排队阻塞。

**步骤：**

1. 对每类操作逐一注入上述失败，并从逻辑请求入队时启动单调计时。
2. 用两个被持有的请求占满全局槽位，再把第三个请求排队至 3 秒，验证期限包含排队。
3. 对同一输入重复两次，记录本地结果、状态机推进和耗时。
4. 在挂起期间操作 HUD、暂停/恢复游戏时钟并统计渲染帧。

**预期：** 每种失败均在入队后不晚于 3.000 秒得到可用本地结果；排队请求不会获得额外传输等待时间。两次本地结果及状态机变化一致。超时远端随后返回也无副作用；主线程、HUD 和时钟控制不冻结。五类操作都能靠各自本地实现完成当前步骤。

### TV2-AT-016 全局/居民并发与十分钟预算（Mandatory）

**追踪：** `TV2-AI-06`、`TV2-AI-05`

**前置：** 使用可控墙钟和记录 token 用量的网关；关闭自动完成，使请求可保持在途。

**步骤：**

1. 三居民同时各提交请求，并让 001 再提交第二个；记录每次传输启动和队列状态。
2. 依次完成请求，检查队列调度及每个请求原始截止时间。
3. 在同一 10 分钟滑动窗口内创建合法会话远程请求，累计到 12 次、18,000 输入 token 或 3,000 输出 token 的各个边界，再提交会超限的请求。
4. 把墙钟推进到最早计量项离开滑动窗口后再提交。

**预期：** 任何时刻全局在途 ≤ 2、每 ResidentId 在途 ≤ 1；001 的第二请求不会并发启动。队列不重置 3 秒期限。达到任一预算上限后，超限请求不启动传输而立即走确定性本地回退，并记录不含正文的预算原因；窗口释放后可再次远程提交。计数与 `TOWN_V2_AI_BUDGET.md` 一致。

### TV2-AT-017 所有者版本变化后的陈旧响应（Mandatory）

**追踪：** `TV2-AI-02`、`TV2-AI-07`、`TV2-SAV-02`

**前置：** 网关可保存并稍后乱序完成合法响应。

**步骤：**

1. 为 001 的活动目标、002 的活动会话和 003 的反思各挂起一个请求，记录 RequestId 与所有者版本。
2. 分别重规划/取消 001 目标、结束 002 会话，并执行一次新演示或读档使 003 版本变化。
3. 以任意顺序返回三条原本 Schema 合法的响应。
4. 比较显示、记忆、目标、行动队列和共享世界前后状态。

**预期：** 协调器尽力取消三请求；每个迟到结果因版本或关联状态不匹配被标记 Stale 并忽略。没有话语显示、记忆写入、目标复活、动作启动或世界变化。审计事件包含 RequestId、ResidentId 和陈旧原因，但不含响应正文。

## 7. 存档、观察与稳定性

### TV2-AT-018 V2 存档 round-trip 与原子拒绝（Mandatory）

**追踪：** `TV2-SAV-01`、`TV2-SAV-02`、`TV2-ID-01`、`TV2-ISO-01`

**前置：** 三居民各有不同日程、目标和私有哨兵；001 有已提交的农务进度，002↔003 会话 Active；三者各有在途请求或预约中的至少一种。

**步骤：**

1. 保存 V2，记录共享世界、居民集合和已提交领域状态；随后任意修改现场并加载。
2. 检查三居民归属、会话、请求、预约和未完成动作处理。
3. 在副本中依次制造重复 ID、缺失 ID、错误外键、未知枚举和越界计数，逐个尝试加载并比较加载前现场。
4. 尝试加载旧版本或未知版本存档。

**预期：** 正常 round-trip 只恢复一份共享世界和三个正确 ID 的私有数据，无串位。活动会话以 `InterruptedByLoad` 结束；请求和旧预约不恢复，居民版本递增；未完成动作从最后已提交状态复检/重规划，不重复扣减或产出。每个损坏存档都在应用前整体拒绝，现场逐字段不变。旧/未知版本必须经明确支持的迁移器成功迁移，或以可理解提示安全拒绝；不得被当成 V2 静默反序列化。

### TV2-AT-019 HUD、结构化追踪与隐私（Mandatory）

**追踪：** `TV2-OBS-01`、`TV2-OBS-02`、`TV2-SEC-01`

**前置：** 运行一次含公开农务、点位竞争、001↔002 私聊、AI 回退和一个陈旧响应的场景；私聊/记忆含唯一哨兵 `PRIVATE-NOT-FOR-PUBLIC-LOG`。

**步骤：**

1. 截图三个居民行、共享时间/背包/农田、动作、目标、日程、会话、AI 模式及回退状态。
2. 从 UI 切换私有记忆检视 001→002→003，再切换命令目标并检查已经入队的命令。
3. 导出公共结构化日志、存档和网关请求摘要；搜索私有哨兵、API Key 形态、Authorization、prompt 和完整私聊正文。
4. 使用关联 ID 还原一次点位竞争和一次陈旧响应的因果链。

**预期：** HUD 可区分三名居民及其 ResidentId，并清楚显示要求的共享/居民状态。检视仅显示当前明确选择的所有者记忆，不赋予居民跨读权限，也不改写已入队命令。公共日志、存档的公共区和请求摘要均不含私有哨兵或凭据；仍可仅凭元数据和 ID 还原预约与请求结果。

### TV2-AT-020 三次确定性复现（Mandatory）

**追踪：** `TV2-CMP-01`、`TV2-SCH-01`、`TV2-NFR-02`

**前置：** 本地 AI 模式；固定初始存档、日程、输入序列和时钟推进序列。

**步骤：**

1. 从同一初始存档完整执行公开农务与一场本地会话，导出规范化领域轨迹。
2. 重复两次；规范化时排除墙钟戳、随机 RequestId 和动画帧数，但保留 ResidentId、分片、阶段、动作、会话结束原因、库存和地块提交。
3. 逐项比较三份轨迹和最终存档快照。

**预期：** 三次的分片、各居民分片内顺序、全局阶段屏障、合法状态提交、会话轮次/结束原因和最终共享/私有状态一致；最终背包均为 `0/0/0/9`。真实并行动画的帧级先后可不同，但不能导致不同领域提交集合、阶段顺序或结果。

### TV2-AT-021 十分钟本地稳定性（Mandatory）

**追踪：** `TV2-NFR-02`、`TV2-NFR-03`、`TV2-ACT-01`、`TV2-RSV-01`、`TV2-CON-01`

**前置：** Development Build 或 Play Mode；本地 AI；配置可重复日程、公开农务和不超过限制的会话触发；开启不变量监视器。

**步骤：**

1. 连续运行 10 分钟真实时间，不使用 Inspector 修改状态。
2. 每帧/状态提交点检查居民动作数、会话数、预约唯一性、请求数、记忆所有者和未处理异常计数。
3. 结束时导出峰值计数、所有会话结束原因、预约表和最终状态。

**预期：** 无未处理异常、主线程冻结、死锁或永久等待；每居民动作 ≤ 1、会话 ≤ 1 且二者互斥；每点位持有者 ≤ 1；无跨居民记忆；所有会话在 6 轮/30 秒内闭合；所有预约最终释放，远程调用数为 0，UI 持续响应。

### TV2-AT-022 远程等待期间主线程响应（Mandatory）

**追踪：** `TV2-NFR-03`、`TV2-AI-05`

**前置：** 远程模式；网关把请求挂起至超时；记录帧和 UI 输入。

**步骤：**

1. 提交一个远程请求，同时连续拖动/点击可用 UI，暂停、恢复并切换允许的时间倍率。
2. 观察三名居民的本地表现和帧计数直到 3 秒回退完成。

**预期：** 3 秒内持续有渲染/Update 帧，UI 输入均得到处理，时钟按用户操作暂停/恢复；请求等待不使用同步阻塞。到期后本地结果接管且不需用户重试。

### TV2-AT-023 MVP 农务领域回归（Mandatory）

**追踪：** `TV2-CMP-02`、`TV2-WLD-01`

**前置：** Unity Test Runner；不安装或更新包。

**步骤：**

1. 运行现有 `FarmPlotTests`、`FarmInventoryTests`、`FarmSimulationTests`、`GameClockTests`、`NpcActionTests` 和与确定性农务规则相关的 `OfflinePlanningTests`。
2. 运行新的三居民分派、共享库存原子提交和阶段屏障 Edit Mode 测试。
3. 检查失败是否仅来自已被 Town V2 明确取代的“场景中恰好一名 NPC”断言；此类场景测试必须更新为 TV2-AT-001，而不能简单删除覆盖。

**预期：** 播种/浇水/施肥/除草/成熟/收获、时间、库存、非法动作无副作用和确定性计划的领域断言全部通过；没有以修改预期数值或移除回归覆盖来掩盖失败。

### TV2-AT-024 可选真实网关烟雾测试（Conditional）

**追踪：** `TV2-AI-02`、`TV2-AI-03`、`TV2-AI-05`、`TV2-SEC-01`

仅当发布说明声称“真实远程 AI 增强已验证”时执行。使用本地 FastAPI 和显式提供的临时环境变量密钥，分别完成一条命令解释、一条会话话轮和一次反思；再中断服务验证自动回退。

**预期：** 所有在线响应经严格 Schema 校验并保持正确 Resident/Goal/Conversation 关联；模型只改变允许的语言表现/高层候选，不改变分片和最终 `0/0/0/9`。中断后从入队起 3 秒内回退，日志、请求证据和仓库中均无密钥。未声明真实在线增强时，本项记为“不适用”，不能代替任何 Mandatory 测试。
